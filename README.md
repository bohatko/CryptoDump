# CryptoDump

Сканер откупов после дампа на фьючерсах OKX (перпетуалы + квартальные фьючерсы).
Подробности расчётов — в [PLAN.md](PLAN.md), карта кода и правила для разработки (и для
AI-агентов) — в [AGENTS.md](AGENTS.md).

## Быстрый старт

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r scanner/requirements.txt   # для разработки: pip install -r requirements-dev.txt

cp .env.example .env            # и впишите TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID

python -m scanner.main --telegram-test                     # проверка бота и чата
python -m scanner.main --print-config                      # посмотреть итоговый конфиг
pytest                                                     # тесты расчётов без сети
ruff check                                                 # линтер
python -m scanner.diag -s BTC,ETH --seconds 30             # что реально доходит до детекции
python -m scanner.main -c scanner/config.example.json
python -m scanner.main -c scanner/config.example.json -s BTC,ETH,SOL --no-telegram
python -m scanner.main --duration 120 --log-level DEBUG    # две минуты и выход
```

Запуск без аргументов использует дефолты из `scanner/config.py` и `.env` из корня проекта.

Запускать из корня проекта, чтобы `python -m scanner.main` нашёл пакет.

## Веб-дашборд

Поднимается вместе со сканером: откройте **http://127.0.0.1:8787**. Интерфейс отвечает
с первой секунды, ещё во время загрузки инструментов.

| Вкладка | Что там |
|---|---|
| Обзор | что сейчас в просадке и почему не алерт, занятые слоты стакана, сводка за 24 ч / 7 дней |
| Алерты | история алертов с фильтрами (инструмент, окно, период, score), карточка алерта |
| Дампы | все просадки выше порога, даже без алерта, и на каком фильтре они отсеялись |
| Инструмент | цена, свечи, просадка по каждому окну против порога, стакан, CVD, ликвидации |
| Настройки | пороги с записью в файл конфига и применением на лету |
| Журнал | последние записи лога с фильтром по уровню |

Кнопки в шапке: «Тихий режим» (алерты пишутся в историю, но не уходят в Telegram и
вебхук), «Тест Telegram», «Перезапуск» (движок пересобирается с конфигом из файла —
так применяются поля «только с рестартом»), «Стоп».

- История хранится в `history.sqlite3` (SQLite из стандартной библиотеки). При первом
  запуске туда импортируется существующий `alerts.jsonl`.
- Настройки сохраняются в файл, переданный через `-c`. Без `-c` правки действуют только
  до перезапуска.
- `--port 8790` — другой порт, `--no-dashboard` — без интерфейса.
- По умолчанию сервер слушает только `127.0.0.1`. Чтобы открыть его в сеть, задайте
  `dashboard.host` и токен в `.env` (`DASHBOARD_TOKEN=...`); без токена на внешнем
  адресе дашборд не поднимется.

### Виртуальный счёт

Вкладка «Счёт» — что было бы, если торговать каждый сигнал: старт 100 $, вся сумма в
сделку с плечом ×5, выход по тейку (2-я цель плана), стопу, безубытку после 1-й цели или
через 2 часа; комиссия 0.05% × 2 и проскальзывание на стопе учтены. Пока позиция открыта,
новые сигналы счёт пропускает; сделки с прибылью/риском ниже 1 не открывает. Прошлые
алерты прогоняются по минутным свечам OKX при старте. Отдельно считается статистика
каждого сигнала (матожидание в % маржи и в R). Правила — секция `paper` конфига или
«Настройки → Виртуальный счёт», затем «Пересчитать с нуля».

### Бэктест на истории

```bash
python tools/backtest.py --hours 24 --top 10 --out tools/out/backtest_24h.csv
python tools/backtest.py --hours 6 -s BTC,ETH,SOL     # быстрый пробный прогон
```

Считает **приближение только по минутным свечам**: стакан (стена покупателя), поток
сделок (CVD — кто агрессивно покупал) и ликвидации в историю не попадают — OKX их не
отдаёт. Поэтому сигнал здесь = одна просадка по порогу окна, без подтверждения
сигнатурами, а пороги окон и правила `paper` берутся те же, что у сканера, — иначе цифры
были бы несравнимы с вкладкой «Счёт». Вариант B — грубый заменитель подтверждения:
только сигналы, где свеча дампа закрылась зелёной.

Вывод: статистика счёта и сигналов, матожидание по окнам, 5 лучших и 5 худших сделок,
плюс автопроверки (тейк в плюсе, стоп в минусе, закрытие не раньше открытия, B ⊆ A).
Ненулевой код возврата — какая-то проверка провалилась.

## Уведомления в Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Добавьте бота в чат/канал и **дайте ему право писать** (для канала — администратором).
3. Скопируйте `.env.example` в `.env` и заполните:

```
TELEGRAM_BOT_TOKEN=123456789:AA...
TELEGRAM_CHAT_ID=-1002592005579
```

4. Проверьте связку: `python -m scanner.main --telegram-test`.

Как это работает:

- токен читается из окружения по имени переменной (`alerts.telegram.token_env`), а не из
  JSON-конфига — секреты не попадают в репозиторий и логи; `.env` уже в `.gitignore`;
- `.env` ищется в текущей папке, затем в корне проекта; переменные процесса имеют приоритет;
- сообщение — готовый план лонга: **что купить, вход «по рынку, не выше», стоп и под чем
  он стоит, три цели с процентами, прибыль/риск** и предупреждения (поздний вход, далёкий
  стоп, слабое соотношение); ниже — почему (стена, поток, ликвидации) простыми словами.
  Как считаются уровни — `PLAN.md` §8;
- чтобы в сообщении был **размер позиции** (монеты, USDT, контракты OKX), задайте риск на
  сделку `trade.risk_usdt` — в дашборде «Настройки → План сделки» или в `config.json`:
  сколько USDT готовы потерять, если сработает стоп;
- на чат действует кулдаун 5 минут (`alerts.cooldown_s`), поэтому один и тот же дамп не
  приходит повторно;
- несколько адресатов — через запятую в `TELEGRAM_CHAT_ID` или в `alerts.telegram.chat_ids`;
- при 429 бот ждёт столько, сколько просит Telegram, при 5xx — повторяет с backoff;
  если разметка не разобралась, сообщение уходит тем же текстом без форматирования;
- `--dry-run` и `--no-telegram` отключают отправку (удобно для отладки порогов).

## Что важно знать

- По умолчанию сканируется **весь рынок** (`market.top_n = 0`, минус инструменты с оборотом
  меньше `market.min_turnover_usdt`): сделки и свечи дешёвые (~300 МБ/час на 511 перпетуалах).
- Стакан берётся из WS-канала `books` (400 уровней, инкременты ~100 мс, без логина), но он
  дорогой (~28 МБ/час на инструмент), поэтому подключается **по требованию**
  (`depth.mode: "ondemand"`): когда у инструмента сработало окно просадки, ему выделяется
  один из `depth.book_slots` слотов на `depth.book_ttl_s` секунд. Альтернативы — `"top"`
  (стакан сразу у самых оборотных) и `"all"` (у всех, только для короткого списка `-s`).
  `books5` (5 уровней) фильтр на 20 уровней не проходит; REST `/market/books` — резерв
  при `depth.source: "rest"`.
- **`sz` у OKX — в контрактах, а не в монетах.** Размер уровня и сделки умножается на
  `ctVal` инструмента из `/public/instruments`, иначе фильтр ликвидности и CVD считались бы
  в контрактах (у BTC-USDT-SWAP один контракт = 0.01 BTC, ошибка в 100 раз).
- Свечи живут на отдельном эндпоинте `wss://ws.okx.com:443/ws/v5/business` (на публичном
  `candle1m` возвращает ошибку 60018). Порт 8443 выводится OKX из эксплуатации — используется 443.
- Стена на бидах считается по среднему уровню ниже лучшего бида и должна простоять
  `wall_persist_s` (10 с): на живом стакане верхний уровень держит почти весь объём,
  а медиана занижена пылью.
- Окна 1m и 5m считаются по сделкам (секундные бакеты), а не по 1m-свечам: свеча,
  пересекающая границу окна, завышала максимум почти вдвое по времени.
- `liquidation-orders` у OKX неполный и публикуется только для SWAP — используется как
  подтверждающий сигнал, не триггер; квартальные фьючерсы опираются на стену и CVD.
- Свежесть стакана в WS-режиме проверяется по всему стакану, а не по каждому уровню:
  биржа присылает только изменения, и неподвижная стена иначе считалась бы мёртвой
  ровно через `stale_level_s` — в момент подтверждения `wall_persist_s`.
- OKX разрешает **480 запросов подписки в час на соединение**; сверх — ошибка
  `60014 Requests too frequent`, а затем биржа перестаёт слать данные. Поэтому подписки
  уходят пачками не чаще 400 в час, ресинк стакана замедляется (5 → 120 с), слот стакана
  держится минимум `depth.book_min_hold_s` (30 с) и не выдаётся снова тому же инструменту
  `depth.book_retry_s` (10 мин), если его просадка заметно не углубилась. Расход — в шапке
  дашборда («WS запросов/ч»).
- Стаканы тяжёлые: через медленный VPN 20 штук забивают канал, и сделки приходят с
  опозданием в секунды. Сканер меряет это («задержка» в шапке дашборда, норма ~0.1 с) и
  при опоздании ≥ 3 с сам урезает число стаканов, а в алерт добавляет «сверьте цену».
  Если задержка не уходит — нужен канал быстрее (другой сервер VPN, VPS рядом с биржей).
- Товарных фьючерсов у OKX нет: `SWAP` + `FUTURES` (включая `quarter`) — это крипто-деривативы.
- Пороги окон меняются на лету: в дашборде или правкой `windows` в конфиге (движок
  перечитает файл по mtime). Смена `market.*`, `depth.levels`, интервала опроса,
  `depth.mode`, `depth.source` и `dashboard.*` (кроме `episode_gap_s`) требует рестарта —
  кнопка «Перезапуск» в дашборде или перезапуск процесса.
